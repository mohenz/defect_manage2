# DefectFlow 로컬 테스트 실행 체크리스트

## 1. 목적
- `defect_manage2` 개발 완료 후 로컬 환경에서 수동 테스트를 수행하기 전에 필요한 준비 상태를 확인합니다.
- 자동 검증 통과 여부, 실행 절차, 수동 확인 항목, 종료 기준을 한 문서에 정리합니다.

## 2. 실행 전 준비
- 작업 경로: [defect_manage2](/d:/Workspace/defect_manage2)
- 포트 확인:
- 수동 실행은 기본 `3000` 포트를 사용하므로, 다른 프로젝트 서버가 떠 있으면 먼저 종료합니다.
- 자동 E2E는 전용 `3001` 포트를 사용하도록 분리되어 있습니다.
- 필수 명령:
- `npm.cmd install`
- `npm.cmd run check:syntax`
- `npm.cmd run test:unit`
- `npx.cmd playwright test tests/e2e/defect.spec.js`
- `npx.cmd playwright test tests/e2e/simple.spec.js`
- 실행 서버:
- `npm.cmd start`
- 기본 접속 주소:
- `http://localhost:3000`

## 3. 자동 검증 통과 기준
- `check:syntax` 전체 통과
- `test:unit` 전체 통과
- 비파괴 E2E 통과
- 홈 로그인 화면
- 테스트벤치 standalone 로그인 복귀
- 테스트벤치 기본 로드

## 4. 수동 테스트 시작 전 확인
- 브라우저 캐시와 기존 로그인 세션 상태를 확인합니다.
- 테스트 계정은 사전에 준비된 계정을 사용합니다.
- 테스트 중 실제 DB 데이터가 변경될 수 있으므로 등록/수정/삭제 시나리오는 별도 기록을 남깁니다.
- popup 차단이 해제되어 있는지 확인합니다.

## 5. 권장 수동 테스트 순서
- 1단계: 홈 진입
  `/` 접속 시 로그인 화면이 정상 표시되는지 확인
- 2단계: 로그인
  테스트 계정으로 로그인 후 대시보드 진입과 메뉴 노출 확인
- 3단계: 목록 화면
  검색, 페이지 이동, 상세 열기, 필터 반영 확인
  페이지 번호가 현재 구간 기준 `10페이지` 단위로 노출되는지 확인
- 4단계: 등록 화면
  신규 등록 폼 진입, 필수값 검증, 공통코드 노출 확인
  기존 결함 수정 진입 시 결함관리번호 `#ID` 표시 및 클릭 복사 알림, 신규 등록 시 숨김 확인
- 5단계: 테스트벤치 연동
  [test_view.html](/d:/Workspace/defect_manage2/test_view/test_view.html)에서 popup 진입, 로그인 복귀, 등록 화면 자동 복귀 확인
  모바일 퀵 등록 화면에서 결함관리번호 영역이 노출되지 않는지 확인
- 6단계: 관리자 화면
  테스트 구분 설정, 공통코드 관리, 저장 오류 로그, 결함조치재확인 탭 진입 확인
  담당자관리 목록이 `15명` 단위로 페이징되는지 확인
- 7단계: 오류 처리
  저장 실패 시 로컬/중앙 오류 로그 흐름이 정상인지 확인

## 6. 로컬 테스트 종료 기준
- 주요 화면 진입 오류 없음
- console 치명 오류 없음
- 자동 검증 전체 통과 상태 유지
- 테스트 중 발견된 특이사항 정리 완료

## 7. 로컬 테스트 완료 후 다음 단계
- 특이사항이 없으면 `git` 반영 준비
- 이후 GitHub Pages / Vercel 전환 체크리스트 기준으로 클라우드 서비스 교체 진행
